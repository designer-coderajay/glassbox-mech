# Public scan: real LLM / RAG / agent regressions (2026-10-05)

**Purpose.** This scan does two jobs:
- (a) find real, reproducible failures to test Glassbox on, for V7 Hard Gate 3 /
  ASSURANCE row V2.4;
- (b) collect public signal on whether "investigate why my AI system behaved
  differently" is a real pain point.

**Method.**
- Read-only searches of the GitHub issues API (llama_index, langchain, haystack,
  open-webui, plus two general queries) and the Hacker News Algolia API, all on
  2026-10-05.
- Issues are cited by number and URL only. No usernames or personal data are recorded.
- This is a keyword-search sample, not a systematic review. It is biased toward issues
  whose wording matched the queries.

**Important caveat.** We have read these issues, so their causes are known to us. Testing
Glassbox on them is a real-system test (they were not injected by us), but it is **not
blind**. A blind test needs someone else to choose and set up a failure without telling
the investigator the cause. See §4.

## 2. Adjacent work found (positioning signal, not verified product claims)

- **haystack #11836**, *Pipeline run recording & deterministic replay — turn every run
  into a shareable, diffable, testable artifact* (open, 14 comments; linked PR #12497) —
  https://github.com/deepset-ai/haystack/issues/11836
  - It proposes record, replay and diff of runs, inside the framework itself.
  - Its stated motivations include being unable to reproduce LLM bugs and unable to
    write deterministic RAG/agent tests.
  - At scan time a maintainer had asked the author to hold the PR while the team
    discussed it internally.
- **Lightbox**: Show HN, 2026-01-27, MIT, v0.1 —
  https://news.ycombinator.com/item?id=46783126
  - It records agent tool calls in a hash-chained, tamper-evident log, with replay and
    diff across versions.
  - Its own post says it does not replay the LLM itself.
- **Cekura**: Launch HN, 2026-03-03, commercial —
  https://news.ycombinator.com/item?id=47232903
  - Simulation-based regression testing of chat and voice agents. It argues that
    turn-by-turn tracing misses session-level failures.

**What this means.**
- **Demand signal.** The problem V7 targets (reproduce, diff and test AI runs) is
  independently named by framework users and by at least two other builders. That is
  evidence the pain is real.
- **Crowding signal.** Record/diff/hash-chain is not novel on its own. A framework
  (Haystack) may build it natively.
- **Remaining differentiator to test.** The pre-registered experiment → intervention →
  evidence-package loop with an explicit claim status (ASSURANCE taxonomy). None of the
  three items above describes that.

This differentiator is an interpretation, not a finding. Whether users value it is
exactly what the interviews (§3) must test.

## 3. Signals about the user problem (from the items above, paraphrased)

- Production LLM bugs are hard to reproduce because runs are ephemeral and stochastic
  (haystack #11836).
- Teams hand-roll mocks for deterministic RAG/agent tests, and those mocks drift
  (haystack #11836).
- Agent failures can live across turns rather than in one call (Cekura launch post).
- Upgrades silently change what context reaches the model (open-webui #25585,
  llama_index #21033).

## 4. Recommended next experiment (V7 Experiment 2), not yet pre-registered

Use **candidate 1** (llama_index #21033):
- **Behaviour change:** trace the sync and async retrieval paths on the issue's repro
  under the buggy version.
- **Intervention:** fix by upgrading to the fixed version.
- **Question:** does the diff place the first divergence at retrieval with the dropped
  node?
- **Blindness:** to raise it, a later run can use a failure chosen by an interviewee.
