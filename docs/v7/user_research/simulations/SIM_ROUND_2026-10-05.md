# SIMULATED forum round, 2026-10-05 (MiroFish-style, 2 rounds)

> **SIMULATION, NOT EVIDENCE.** Five fictional personas (S1–S5, the same ones as in
> `SIM_2026-10-05_SYNTHESIS.md`), each played by a separate LLM agent.
>
> **Do not:**
> - count it toward the five-user decision rule;
> - cite it in ASSURANCE (row V5 stays `HYPOTHESIS`);
> - quote it anywhere as user research.
>
> **Purpose:** see which objections to an honest announcement spread between personas,
> and which die out. It does not replace the MiroFish app, and it does not replace real
> interviews.

## Method

- **Seed post.** It describes only what is built (same content as
  `MIROFISH_SEED_V7.md` §3):
  - local trace, hash-only by default;
  - first-divergence diff;
  - integrity-checked evidence bundle;
  - explicit "does NOT do yet" list;
  - two non-blind experiments.
- **Round 1.** Each persona saw only the post and answered independently. Each could
  scroll past.
- **Round 2.** Each persona saw the full thread (summarised) and replied. The author did
  not reply in between, deliberately, to see which questions persist when nobody answers
  them.
- **Limits.** 5 agents and 2 rounds. All agents are the same underlying model, so
  "agreement" between them partly reflects shared priors, not independent opinions. The
  personas and their incidents were written by the assistant.

## Which objections spread (raised or endorsed by ≥3 personas by round 2)

1. **Run-to-run noise / need a baseline (S2, S5 → endorsed by S1, S4).** Every persona
   that reasons about first divergence on LLM output asks: compared with what normal
   variation? It is the most contagious objection in the thread.
2. **Multiple simultaneous causes (S4, S5 → endorsed by S2, S3, S1).** "First divergence
   shows the earliest difference and you stop looking." Four personas named the
   one-change-at-a-time re-runs (on the "not yet" list) as the feature they actually
   want.
3. **Hash-only hides *what* changed (S1, S2, S3, S5).** Personas read hash-only as "can't
   see content". The opt-in `redacted`/`full` policies exist in the recorder but were
   **not mentioned in the post**, so this is partly a *messaging* gap, not only a
   feature gap.
4. **Import from existing tracing instead of re-instrumenting (S1 LangSmith, S3 Langfuse,
   S4 OTel).** Nobody wanted to add a second tracing layer by hand.

## Which objections did not spread

- **Detection** (S1, S4) was repeated by its two raisers, but the others did not pick it
  up as a blocker. They accepted it as out of scope.
- **The evidence bundle and signing** stayed with S3 only (consistent with H5: it matters
  where someone signs off).
- **"Neither test was blind"** was noted (S3, S4) and earned credit for honesty, but was
  not a reason to dismiss the post.

## Compared with the interview simulation (H1–H5)

| H2 attribution across simultaneous changes | **Strengthened.** It became the central feature request |

Agreement between two simulations driven by the same model is **not** confirmation. Only
the real interviews count.

## What this suggests (hypotheses for the owner, not decisions)

1. **Messaging fix (cheap, no code).** Any future post should state that content capture
   is opt-in (`redacted` / `full`), and that hash-only is only the default. Three of five
   personas assumed otherwise.
2. **Candidate next build, if real interviews agree:** a noise-baseline diff (good-vs-good
   and group-vs-group) before any automation of re-runs. It is the precondition for both
   H2 and H4, and the V6 run-level statistics work is directly relevant.
3. **An adapter from OTel spans** would answer S1, S3 and S4 at once, since LangSmith and
   Langfuse both have OTel-related integrations. *I have not verified current
   LangSmith/Langfuse OTel export capabilities. Check their docs before relying on this.*
4. **Do not post publicly yet.** In this simulation, the honest post as built would get
   questions, not users. Wait until at least one of the noise baseline or the re-runs
   exists, and the real interviews are done.
